# KnowTrace AI MVP 范围

## 解决的问题

团队资料往往分散在会议纪要、需求文档、表格、PDF 与历史笔记中。通用聊天无法说明回答基于哪份资料，也容易跨项目混用上下文。KnowTrace 将资料、处理任务和会话固定在同一工作区，并保留每个回答的检索证据。

## 首期用户

- 需要整理和复核内部资料的个人或小团队。
- 产品、研究、运营、交付等会持续沉淀文档并需要基于文档追问的角色。

## 首期能力

- 工作区及独立文件、会话范围。
- PDF、DOCX、TXT、Markdown、CSV、XLSX 的上传与私有存储。
- Redis Worker 异步解析、切片、Embedding、失败重试和 SSE 任务进度。
- 基于 pgvector 与 PostgreSQL 全文检索的工作区内混合检索。
- 基于 LangChain 的流式 RAG 回答、历史消息与可展开引用片段。

## 明确不做

- 团队协作、角色权限和计费。
- 本地模型管理、模型市场、多模型路由和复杂 Agent 工具调用。
- 联网搜索、网页抓取、OCR 与图片内容理解。
- 自动修改或生成业务资料；系统只基于用户已上传的资料回答。

## 验收闭环

1. 创建工作区并上传一份可解析资料。
2. 在任务状态中等待解析和向量索引完成。
3. 在同一工作区提出问题。
4. 观察流式回答及其文件名、片段序号和摘录。
5. 刷新页面或切换对话，确认历史消息与引用仍可读取。
