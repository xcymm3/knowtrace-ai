# KnowTrace AI 面试题标准答案

以下答案对应《interview-foundations.md》中的知识点。实际面试时不必逐字背诵，可以保留自己的表达习惯。

## 1. 请介绍一下 KnowTrace AI 项目。

KnowTrace AI 是一个可追溯的个人知识库工作台。用户上传资料后，系统会解析文本、切块、向量化并建立索引；提问时只从当前工作区检索相关资料，再让大模型基于资料回答。回答会带文件和文本片段引用，用户可以核对答案依据。

## 2. 这个项目解决了什么问题？

普通 AI 问答容易出现答案没有来源、用户难以核对的问题，而且资料分散在不同文件中。这个项目把资料集中到私有工作区，用检索找到依据，并把回答和原文 chunk 建立引用关系，提升了资料问答的可信度和可核对性。

## 3. React 组件是什么？

React 组件通常是一个返回 JSX 的函数，用来描述页面中的一块可复用界面。它可以通过 props 接收父组件传入的数据，通过 state 管理自己会变化的数据。例如文档卡片组件接收文件名和处理状态，再渲染文档信息。

## 4. props 和 state 的区别是什么？

props 是父组件传给子组件的输入，子组件不应该直接修改。state 是组件自己维护、会随交互或请求结果变化的数据，使用 setState 类的更新函数修改。比如文档名称可作为 props，输入框内容和请求 loading 状态可作为 state。

## 5. 为什么列表渲染需要 key？

key 让 React 识别列表中每一项的身份，从而正确进行更新、删除和移动。文档列表应该使用稳定的文档 ID 作为 key。若列表会变化，使用数组下标可能导致 React 误把一项的状态复用到另一项。

## 6. useEffect 用来做什么？

useEffect 用来处理渲染之外的副作用，例如请求接口、订阅事件或设置定时器。比如 workspaceId 改变后重新加载该工作区文档。需要注意依赖项，并在组件卸载或请求过期时清理订阅或取消请求，避免旧数据覆盖新页面。

## 7. TypeScript 的实际价值是什么？

TypeScript 在开发和构建阶段检查类型，能更早发现接口字段拼错、漏处理空值、参数类型不对等错误。在前后端项目中，我会为请求和响应定义清楚的类型，让接口变更更容易发现影响范围。

## 8. any 和 unknown 有什么区别？

any 基本关闭了类型检查，后续可以任意访问属性或调用方法，容易把错误留到运行时。unknown 更安全，使用前必须通过 `instanceof` 或类型判断收窄。外部输入和 catch 到的异常更适合先用 unknown。

## 9. 什么是泛型？

泛型让代码在复用时仍能保留具体类型。例如通用的 `requestJson<T>` 函数可以根据调用处的 T 返回文档数组、工作区对象等不同数据，而调用方能获得类型提示和检查。

## 10. Next.js 和 React 的关系是什么？

React 主要负责用组件构建界面；Next.js 是基于 React 的应用框架，提供路由、构建、服务端渲染和接口路由等工程能力。本项目使用 Next.js 组织前端页面，使用 React 完成交互界面。

## 11. 什么情况下需要 Client Component？

需要 `useState`、`useEffect`、点击事件、文件选择或浏览器 API 的组件需要是 Client Component，在文件顶部加 `"use client"`。例如上传文件、输入问题和读取 SSE 流的部分。静态布局或可在服务端完成的数据展示不一定需要。

## 12. 为什么这个项目还要用 FastAPI，而不是全部写在 Next.js 中？

Next.js 可以提供轻量接口或 BFF，但本项目的核心后端涉及文件解析、向量化、任务调度和 RAG，Python 的相关生态更合适，所以由 FastAPI 承担主要业务 API。Next.js 负责前端应用，两者通过 HTTP 接口通信，也可以独立部署和测试。

## 13. GET、POST、PATCH、DELETE 分别适合什么场景？

GET 用于读取，例如获取文档列表；POST 用于创建或触发动作，例如创建工作区、上传文件、发起提问；PATCH 或 PUT 用于修改，例如改工作区名称；DELETE 用于删除文档或会话。

## 14. 前后端联调时，发现接口不通会如何排查？

我会先在浏览器 Network 看请求是否发出，确认 URL、HTTP 方法、请求头、token 和请求体是否符合接口契约，再看状态码和响应内容。然后结合后端日志定位。常见原因是字段不一致、鉴权 token 缺失或过期、跨域、参数格式错误或后端异常。

## 15. 401 和 403 的区别是什么？

401 通常表示未认证，例如没有登录、token 过期或 token 无效。403 表示身份已确认，但没有权限访问目标资源。例如用户登录后尝试读取其他用户的私有工作区。

## 16. 认证和授权有什么区别？

认证回答“你是谁”，项目中用户登录后由 Supabase Auth 签发 JWT。授权回答“你能做什么”，后端根据 JWT 中的用户身份检查工作区和文档是否归属于当前用户。前端隐藏按钮不能替代后端授权校验。

## 17. SSE 是什么，项目里为什么使用它？

SSE 是服务器通过一个持续的 HTTP 连接不断向浏览器推送事件的方式。项目中大模型生成回答需要时间，所以后端把 token 文本片段持续推给前端，前端边收到边显示。用户不需要等到完整答案生成才看到结果。

## 18. 为什么不直接使用 EventSource？

原生 EventSource 主要用于 GET 请求，而提问接口需要用 POST 发送问题，并且要携带鉴权信息。项目使用 fetch 发起请求，再用 `response.body.getReader()` 分块读取 SSE 响应，更适合这个场景。

## 19. PostgreSQL 在项目里保存哪些数据？

它保存长期业务数据，例如用户关联信息、工作区、文档元数据、处理任务、文本 chunk、向量、会话、消息和回答引用关系。原始大文件不放数据库表里，而是放到 Storage，数据库保存其对象路径和元数据。

## 20. 什么是主键、外键和索引？

主键唯一标识一行，例如文档 ID。外键表达表之间的引用关系，例如文档的 workspaceId 指向工作区。索引用来加速常见查询，例如按 workspaceId 查文档；但索引也增加写入和存储成本，不能无节制添加。

## 21. 为什么 SQL 要使用参数化查询？

参数化查询把 SQL 结构和用户输入分开，避免用户输入被当作 SQL 指令执行，从而防止 SQL 注入。它也能让代码更清晰，减少字符串拼接导致的转义错误。

## 22. 什么是事务？

事务把多个数据库操作作为一个整体执行：要么都成功，要么失败后回滚。例如创建文档记录和任务记录应保持一致。涉及 Storage 或 Redis 等外部服务时，不能完全依赖数据库事务，需要考虑部分成功后的补偿和重试。

## 23. Supabase Storage 是什么？和浏览器 localStorage 有什么不同？

Supabase Storage 是云端对象存储，用来保存原始 PDF、Word、Excel 文件和解析后的文件产物。它是远程持久化文件服务，可跨设备使用并受权限控制。浏览器 localStorage 只在用户本机浏览器中保存少量数据，容易被清理，不能作为项目文件仓库。

## 24. Redis 是附属于 PostgreSQL 吗？

不是。Redis 和 PostgreSQL 是独立服务。PostgreSQL 负责长期持久化业务数据；Redis 在这个项目的 Docker 部署里主要用于临时异步任务队列。它们由应用代码协调使用。

## 25. ARQ Worker 是什么，为什么需要它？

ARQ 是 Python 的异步任务队列库，ARQ Worker 是独立运行的任务消费者。上传后 API 将任务投递到 Redis，Worker 再完成文件下载、解析、切块、向量化和写库。这样耗时任务不会占住 HTTP 请求，用户可看到进度，也更容易重试失败任务。

## 26. 什么是 RAG？

RAG 是检索增强生成。它在用户提问时先从知识库检索相关文本 chunk，再把这些内容和问题一起交给大模型生成答案。这样回答更贴近用户资料，也能给出来源引用，而不是仅依赖模型已有知识。

## 27. 什么是向量检索和混合检索？

向量检索会把文本和问题转换成向量，通过相似度找到语义接近的 chunk。全文检索更擅长精确术语和数字。混合检索把两者结果融合，兼顾语义匹配和关键词匹配，提高召回质量。

## 28. 如何实现回答可追溯？

每个 chunk 都保存所属文档和位置；生成回答时保存回答与被使用 chunk 的结构化引用关系，例如 answerId 和 chunkId。前端从这份关系展示文件名、片段和跳转入口。这样刷新后仍可恢复引用，也能在删除文档时清理关联数据。

## 29. 什么叫端到端 Ownership？

它指对用户最终拿到的结果负责，而不只是写完自己分到的一段代码。包括理解需求和验收标准、设计接口和异常处理、推动联调、测试完整路径、上线后跟进问题。项目里上传功能的责任范围包含上传、处理状态、解析索引、失败重试、问答引用和删除清理。

## 30. 这个项目如何保证用户数据隔离？

用户登录后得到 JWT，前端请求携带 token，后端验证 token 后取得当前用户身份。后端查询工作区、文档和检索 chunk 时都检查归属和 workspace 边界；Supabase RLS 再从数据库层限制用户只能访问自己的行。私有文件也不能直接公开，而要经过权限校验后访问。
